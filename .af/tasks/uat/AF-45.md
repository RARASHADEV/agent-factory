# Executor adapter (AfCliExecutor + StubExecutor) with TokenUsage reporting

## Objective
Implement the Executor seam — a one-method interface (`run(agentId, input) → AgentResult`) that invokes AF CLI and returns output plus normalized token usage. Keeps orchestration independent of execution.

## Context
Epic AF-41. Spec: `docs/tech-design-orchestration.md` §5.1. Thin adapter — no model logic (routing is AF CLI's job, AF-42). `AfCliExecutor` (prod) + `StubExecutor` (tests). `AgentResult` carries `usage: TokenUsage`; usage is **measured from the backend**, not estimated.

## Acceptance
- [ ] `Executor.run(agentId, input)` dispatches via AF CLI and returns `{ output, usage }`
- [ ] `TokenUsage` normalized across backends (Claude `input/output_tokens`; Ollama `prompt_eval_count/eval_count`; vLLM `prompt/completion_tokens`)
- [ ] `StubExecutor` returns canned results + usage for orchestrator unit tests (no models)
- [ ] No model/backend branching in the executor itself

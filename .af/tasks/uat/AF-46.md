# Orchestrator engine: constrained-dynamic supervisor + guardrails

## Objective
Build the domain-agnostic orchestrator: run the supervisor, expose roster agents as tools, let it delegate dynamically, and enforce guardrails. Returns a structured result with `stopReason` and `totalUsage`.

## Context
Epic AF-41. Spec: `docs/tech-design-orchestration.md` §3 (control loop), §5.2 (interface), §6.6 (guardrails). Supervisor mode = **constrained-dynamic** (Option B). Calls the Executor (AF-45); consumes domain config (AF-43). Model-agnostic.

## Acceptance
- [ ] `Orchestrator.run(domain, objective, opts)` runs the constrained-dynamic loop and returns `OrchestrationResult`
- [ ] Input validation throws before any dispatch (empty objective, unresolved slugs) — §6.1
- [ ] Guardrails enforced: `max_delegations`, `roster_only`, `token_budget` (running total), `timeout_seconds`, `required_finalizers`, `max_revision_loops`, `abort_on_no_progress`
- [ ] `parallelizable` agents fan out concurrently
- [ ] Result reports `stopReason` + `totalUsage`; `dryRun` logs the plan without dispatching
- [ ] Unit-tested against `StubExecutor` (no live models)

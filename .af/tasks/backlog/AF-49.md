# Local-backend orchestration: add a backend:local roster agent + domain to verify Ollama/vLLM end-to-end

## Objective
Exercise the local LLM execution path (Ollama/vLLM) end-to-end through the
orchestrator. AF-48 wired `af orchestrate` and proved per-step `backend`
attribution (AF-FIX-A6) via the wired executor, but **no roster agent declares
`execution.backend: local`**, so the local-model dispatch path has never been
run in a real orchestration. This ticket adds the missing content + config and
verifies a real local-backed run.

## Context
Surfaced during AF-48 QA (`.af/output/AF-48/AF-48-qa-verdict.md`) and flagged in
the AF-48 design §8.1/§12 as the second of two content dependencies (the first —
a supervisor that emits parseable decisions — was resolved by
`agents/orchestration-supervisor.md`). The execution engine itself already
supports local routing: `ENABLE_AF_42=true`, `dispatchAgent` → `dispatchLocal`
with the `LOCAL_ENDPOINT_ALLOWLIST` SSRF guard (localhost/127.0.0.1/::1 by
default, overridable via `AF_LOCAL_ENDPOINT_ALLOWLIST`). What's missing is an
agent + domain that actually requests `backend: local`.

This is **content/config authoring**, not engine code — no `src/` changes
expected beyond, optionally, a test.

## Acceptance
- [ ] At least one roster agent declares an `execution` block with
      `backend: local`, a `model`, and an allow-listed `endpoint` (e.g. a local
      Ollama or vLLM `/v1` endpoint on localhost)
- [ ] A domain YAML in `orchestration/domains/` wires the existing
      `orchestration-supervisor` to a roster that includes the local-backed agent
- [ ] A real `af orchestrate <domain> "<objective>"` run (with `ENABLE_AF_48=true`
      and a local model serving) completes with at least one step whose
      `backend` is the local backend (never `'unknown'`), a sane `stopReason`,
      and measured `totalUsage` — captured in this ticket's log
- [ ] The endpoint used is covered by `LOCAL_ENDPOINT_ALLOWLIST` (no allow-list
      widening required); document the model + endpoint used
- [ ] Decision on `ENABLE_AF_48` flip-on documented (this run plus the existing
      Claude-backed path together satisfy design §10 flip-on criteria)

## Notes
- Requires a local model server (Ollama or vLLM) available to the test machine;
  if none is available in CI, the verification run is a documented manual step.
- Keep all backend/model routing in `dispatchAgent` — the new content only
  declares frontmatter; it must not introduce routing logic (AF-48 design §2.1).
- Pairs with AF-48 (`af orchestrate`) and AF-42 (local backend routing).

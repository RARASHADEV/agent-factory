# Pipeline Flow 4: Pipeline run command — af pipeline run

## Objective

Build the `af pipeline run <name> --task <ticket>` command that executes a multi-agent pipeline end-to-end. This is the main entry point for autonomous SDLC execution — it reads a pipeline definition, runs each phase's agent in sequence (respecting dependencies), injects artifacts between phases, and stops on failure.

## Context

Part of the Pipeline series (AF-23 → AF-28). This is the **integration ticket** that ties together AF-23 (structured output), AF-24 (pipeline definitions), and AF-25 (artifact injection). Depends on all three.

This is the highest-complexity ticket in the series. It introduces a new command namespace (`af pipeline`) and a pipeline execution engine.

## Solution

1. **Create `src/commands/pipeline.ts`** with:
   - `pipelineRunCommand(name: string, options: { task: string, project?: string, dryRun?: boolean, from?: string })`:
     - Load pipeline definition via `loadPipeline()` (AF-24)
     - Resolve the task via the project's TaskProvider
     - Topologically sort phases based on `requires` dependencies
     - For each phase in order:
       a. Log `pipeline.phase_start` to audit
       b. Resolve artifact injections from prior phases via `injectArtifacts()` (AF-25)
       c. Compose system prompt (agent + project + task + context + injected artifacts)
       d. Spawn the agent via the SDK (background mode, using `runAgent()` from `src/lib/sdk.ts`)
       e. Wait for completion (poll `status.json` or await the promise)
       f. Read `result.json` (AF-23) and evaluate gate condition
       g. If gate passes → continue to next phase
       h. If gate fails → stop pipeline, log failure, report which phase and why
     - Move task status based on pipeline progress (e.g., backlog → in-progress on start, → ready-for-qa after implement, etc.)

2. **Pipeline state tracking** — write `.af/output/{ticket}/pipeline-state.json`:
   ```json
   {
     "pipeline": "sdlc",
     "ticket": "AF-30",
     "startedAt": "...",
     "currentPhase": "implement",
     "phases": {
       "design": { "status": "completed", "agent": "architect", "startedAt": "...", "completedAt": "...", "gateResult": "pass" },
       "implement": { "status": "running", "agent": "engineer", "startedAt": "..." }
     }
   }
   ```

3. **`--from <phase>` flag** — resume a pipeline from a specific phase (skip earlier phases, assume their outputs exist). Useful for retrying after a failure.

4. **`--dry-run` flag** — print the execution plan (phase order, agents, injections) without spawning anything.

5. **Register in CLI** — add `af pipeline run` and `af pipeline list` subcommands in `src/cli.ts`.

6. **New audit events**: `pipeline.start`, `pipeline.phase_start`, `pipeline.phase_complete`, `pipeline.phase_fail`, `pipeline.complete`, `pipeline.fail`.

## Acceptance
- [ ] `af pipeline run sdlc --task AF-30` executes the SDLC pipeline end-to-end
- [ ] Phases run in dependency order (topological sort)
- [ ] Artifacts from prior phases are injected into subsequent agent prompts
- [ ] Gate conditions are evaluated after each phase; pipeline stops on gate failure
- [ ] `pipeline-state.json` is written and updated as phases progress
- [ ] `af pipeline list` shows available pipelines
- [ ] `--dry-run` prints execution plan without spawning
- [ ] `--from <phase>` resumes from a specific phase
- [ ] Audit events are logged for pipeline lifecycle
- [ ] Task status is updated as pipeline progresses
- [ ] Pipeline stops cleanly on agent failure (non-zero exit / spawn error)

# Completion callbacks on every terminal state

> **Epic:** AF-53 — AF Service over HTTP (`af serve`) · **Stage A (execution plane)** · **Seq 4 of 4 — completes the ORA-160 dependency**
> **Design:** `docs/designs/AF-53-service.md` §5.2 · **Consumer:** ORA-160 / ORA-119 callback contract · **Flag:** `ENABLE_AF_53`
> **Depends on:** AF-56 (queue emits terminal events) · **Blocks:** AF-61 (deploy)

## User Story
As **ORA's callback server**, I want `af serve` to POST me the result of every job exactly once on any terminal state, **so that** I never poll `af agent status` and never hang waiting on a worker that crashed or timed out.

## Context
Producer side of the ORA-160 §Phase 2 contract; AF-53 is what makes ORA-160's "deterministic dispatch" deterministic. On **every** terminal state — `completed | failed | crashed | timeout` — POST `{ task_id, status, result }` to the job's `callback_url` (recorded in the registry, AF-55). This removes model-driven polling: the result is always pushed, exactly once.

## Acceptance
- [ ] Callback fires on all four terminal states: `completed | failed | crashed | timeout` (design test 4).
- [ ] Exactly once per job; killed/timed-out/crashed worker still produces one `failed` callback with **no hang** (design test 4).
- [ ] Payload matches the ORA-119 contract `{ task_id, status, result }`.
- [ ] Success path delivers `completed` with the result body.
- [ ] Callback delivery failures are retried/logged, never silently dropped.

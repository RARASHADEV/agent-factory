# Query routes (read plane)

> **Epic:** AF-53 — AF Service over HTTP (`af serve`) · **Stage B (full surface)** · **Seq 6 (parallel with AF-60)**
> **Design:** `docs/designs/AF-53-service.md` §4 (query plane), §1 (sync, unqueued) · **Flag:** `ENABLE_AF_53`
> **Depends on:** AF-58 (core ops), AF-54 (server) · **Blocks:** AF-61 (deploy)

## User Story
As a **remote client (any authenticated AF consumer)**, I want synchronous read endpoints for projects, status, tasks, agents and pipelines that never go through the queue, **so that** I can inspect fleet state instantly even while 20 jobs are running.

## Context
The query plane is fast request/response and **never queued** — you would not make `GET /projects` wait behind 20 running agents (§1). Each handler is a thin adapter over an AF-58 core op returning JSON. Same auth + project guardrail as the rest of the surface.

## Acceptance
- [ ] Routes per §4: `GET /projects`, `GET /projects/:p/status`, `GET /projects/:p/tasks?status=`, `GET /tasks/:ticket`, `GET /agents`, `GET /agents/:slug`, `GET /pipelines`, `GET /pipelines/:ticket`.
- [ ] Unqueued: `GET /projects` returns immediately while 20 jobs run (design test 6).
- [ ] A representative route returns the **same data** as the equivalent `af` CLI command (parity, design test 7).
- [ ] Auth enforced (401) and project-scoped routes reject unknown `project` (400).

# Log-first/log-last audit middleware + GET /audit overview service

> **Epic:** AF-53 — AF Service over HTTP (`af serve`) · **Stage A (observability)** · **Seq 3 (parallel with AF-56)**
> **Design:** `docs/designs/AF-53-service.md` §1.1, §5.4, §4 (`GET /audit`), §7.2 (`request_log`), §7.3 (`job_events`) · **Flag:** `ENABLE_AF_53`
> **Depends on:** AF-54 (server), AF-55 (SQLite tables) · **Blocks:** AF-61 (deploy)

## User Story
As the **platform operator**, I want every request the service handles — job, inquiry, and instruction — logged to SQLite on arrival and again on completion, and exposed through a `GET /audit` overview, **so that** I can see at any moment what work is running and have a complete, queryable history of everything the service has ever done.

## Context
This is the headline capability of the SQLite redesign (project-owner directive 2026-06-04). It is the cross-cutting **audit middleware** that wraps **every** route on all three planes and implements the §5.4 flow: **request → ① log → ② AF → ③ log → ④ consumer**. AF-55 owns the schema/data-access; **this ticket owns the writes and the read endpoint**. Storage is the `request_log` (cross-plane journal) and `job_events` (execution lifecycle) tables from §7. Self-contained within AF — no ORA/external consumer involved.

## Acceptance
- [ ] **Log-first (①):** before any routing/work, a `request_log` row is written with `received_at`, `caller`, `plane`, `method`, `path`, `operation`, `project`, and `payload` — with the `Authorization` bearer and any secret-bearing fields **stripped** (design tests 12, 14, §9).
- [ ] **Log-last (③):** the same row is updated with `status`, `outcome`, `result_summary`, `responded_at` **before** the response (or callback) is delivered (design test 12).
- [ ] Rejected requests (`401`/`400`/`429`) still produce a `request_log` row — attempts are recorded, not just successes (design test 12).
- [ ] **Execution lifecycle (`job_events`):** each transition (`queued`/`started`/`completed`/`failed`/`crashed`/`timeout`/`callback_sent`/`callback_failed`) is appended; the terminal event is timestamped at or before `callback_sent` (design test 13). Wires into the queue (AF-56) and callbacks (AF-57).
- [ ] **`GET /audit`** returns the journal across all three planes with `?since=&caller=&project=&plane=&op=&limit=` filters; **unqueued** (returns immediately while 20 jobs run) (design test 13).
- [ ] No secret/credential is ever persisted in `request_log.payload` (design test 14, §9).
- [ ] Auth enforced on `GET /audit` (401); reads use WAL concurrent reads, never blocking writers.

# Pipeline Flow 5: Gate evaluation — pass/fail checks between pipeline phases

## Objective

Build a robust gate evaluation engine that checks whether an agent's structured output meets the conditions required to proceed to the next pipeline phase. This goes beyond the basic field checks in AF-26 to support compound conditions, custom gate functions, and actionable failure reporting.

## Context

Part of the Pipeline series (AF-23 → AF-28). Depends on AF-26 (pipeline runner exists with basic gate checks). This task hardens and extends gate evaluation.

AF-26 implements a minimal gate check (field + operator + value). This task adds:
- Compound gates (AND/OR of multiple conditions)
- Richer operators (regex match, numeric comparisons, array contains)
- Human-readable failure reports explaining *why* a gate failed and *what to do*
- Optional auto-retry behavior (re-run the failed phase N times before giving up)

## Solution

1. **Extend `GateCondition`** in `src/lib/pipeline.ts`:
   ```typescript
   interface GateCondition {
     field: string;             // dot-path into result.json (e.g., "metadata.verdict")
     operator: 'eq' | 'neq' | 'exists' | 'not_exists' | 'contains' | 'matches' | 'gt' | 'lt' | 'gte' | 'lte';
     value?: any;               // expected value (not needed for exists/not_exists)
   }

   interface GateSpec {
     all?: GateCondition[];     // AND — all must pass
     any?: GateCondition[];     // OR — at least one must pass
     // Shorthand: a single GateCondition at top level (backward compat with AF-26)
     field?: string;
     operator?: string;
     value?: any;
     // Retry config
     retry?: number;            // max retries on failure (default: 0)
   }
   ```

2. **Create `src/lib/gate-evaluator.ts`**:
   - `evaluateGate(gate: GateSpec, result: ResultSchema): GateResult`
   - `GateResult`: `{ passed: boolean, failures: GateFailure[] }`
   - `GateFailure`: `{ condition: GateCondition, actual: any, message: string }`
   - Supports dot-path field access (e.g., `metadata.pr_url` → `result.metadata.pr_url`)
   - Clear error messages: "Gate failed: expected metadata.verdict to eq 'PASS', got 'FAIL'"

3. **Integrate with pipeline runner** (AF-26): replace the inline gate check with `evaluateGate()`. On failure, log the `GateFailure[]` details to audit and pipeline state.

4. **Optional retry**: if `retry: N` is set and a gate fails, re-run the phase up to N times before declaring failure. Useful for flaky agents.

## Acceptance
- [ ] `evaluateGate()` function exists in `src/lib/gate-evaluator.ts`
- [ ] Supports operators: eq, neq, exists, not_exists, contains, matches (regex), gt, lt, gte, lte
- [ ] Supports compound gates: `all` (AND) and `any` (OR)
- [ ] Backward compatible with simple single-condition gates from AF-26
- [ ] Dot-path field access works (e.g., `metadata.verdict`, `artifacts[0].path`)
- [ ] Gate failures produce human-readable messages with expected vs. actual values
- [ ] Retry logic re-runs the phase up to N times on gate failure
- [ ] Pipeline state records gate evaluation results per phase

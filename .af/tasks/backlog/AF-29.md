# Bug: af task log fire-and-forget causes comments to never reach Loka

## User Story

As a user managing tasks through the AF CLI, I want my log entries to reliably appear as comments in the Loka UI, so that my team can follow task progress without having to read local markdown files.

## Objective

Fix the `af task log` command so that Loka comment sync completes before the CLI process exits. Currently, log entries are written locally but the HTTP POST to Loka is fire-and-forget — the process exits before the request finishes, so comments never arrive.

## Context

**Discovered during:** Pipeline task creation (AF-23 through AF-28). Ran `af task log` on all 6 tasks to add reference comments. All 6 logged locally (`synced-log-count` was updated in frontmatter), but zero comments appeared in Loka. Had to POST them directly via `curl` to fix.

**Root cause in code:** `src/commands/task.ts` line 207:
```typescript
void postActionSync(afPath, meta, ticket.toUpperCase(), 'log', { logEntry: entry });
```

The `void` keyword discards the promise — the async HTTP POST to Loka starts but the Node process exits immediately after `console.log(success(...))`. The `postActionSync` function itself is correct (it calls `syncLogEntries()` which POSTs to `/tasks/{id}/comments`), but it never gets a chance to finish.

**Scope of impact:** Every `af task log` call. No log entry has ever reliably synced as a Loka comment unless the process happened to stay alive long enough (e.g., when called from a long-running agent spawn).

**Same pattern exists in:** `af task create` (line 107), `af task move` (line 161), `af task assign` (line 189) — all use `void postActionSync(...)`. These may have the same issue but are less visible because their primary mutations (create task, change status, change assignee) happen via the provider directly, and `postActionSync` is a secondary sync. For `log`, the Loka POST IS the primary side effect, so dropping it is a total failure.

## Solution

Change `void postActionSync(...)` to `await postActionSync(...)` in `taskLogCommand()`. Consider doing the same for the other task commands (`create`, `move`, `assign`) for consistency.

If awaiting is too slow for the user experience, an alternative is to add a short grace period (e.g., `await Promise.race([postActionSync(...), sleep(5000)])`) so the process waits up to 5 seconds for sync to complete.

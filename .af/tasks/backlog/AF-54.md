# af serve skeleton + auth + /health

> **Epic:** AF-53 — AF Service over HTTP (`af serve`) · **Stage A (execution plane)** · **Seq 1 of 4**
> **Design:** `docs/designs/AF-53-service.md` §3.2, §8, §9, Decision 4, §14 (flag spec) · **Flag:** `ENABLE_AF_53`
> **Depends on:** — (epic root) · **Blocks:** AF-55, AF-56 (and transitively all of Stage A/B)

## User Story
As an **AF platform operator**, I want a flag-gated `af serve` HTTP process that binds only to the Tailscale interface and authenticates every request, **so that** AF capabilities can be reached through one governed door instead of ad-hoc `ssh hanuman … af …` / `bash → af`.

## Context
Foundation ticket for the whole epic — every other AF-53 child mounts its routes on this server. Build on Node's built-in `http` (the pattern `af webhook serve` already uses), **not** express/fastify. Mirror ORA-119 `checkAuth`, comparing the bearer secret with `crypto.timingSafeEqual` (the constant-time comparison already in `src/lib/webhook-handler.ts`). Do **not** copy `webhook serve`'s `0.0.0.0` bind (Decision 4 / §14 R2).

## Acceptance
- [ ] Unauthenticated request → `401`; wrong secret → `401` (design test 1).
- [ ] Binds to host Tailscale IPv4 (`tailscale ip -4`, `AF_SERVICE_BIND`); **fails to start** (non-zero, binds nothing) if it would resolve to `0.0.0.0`/public unless `AF_SERVICE_ALLOW_PUBLIC=true` (design test 9, Decision 4).
- [ ] `GET /health` → `{ ok, running, queued, capacity: 20 }`.
- [ ] With `ENABLE_AF_53` off: prints a "disabled" notice, exits 0, opens no listener (flag check at command entry, mirroring `webhook`'s `ENABLE_AF_12`).
- [ ] Port defaults to `4150` (`AF_SERVICE_PORT`); config lives under a new `service` block in `GlobalConfig`.

## Sequencing

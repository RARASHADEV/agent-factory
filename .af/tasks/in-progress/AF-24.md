# Pipeline Flow 2: Pipeline definition format — YAML schema + parser

## Objective

The pipeline orchestrator needs a declarative way to define which agents run in what order, what they pass to each other, and what conditions must be met before proceeding. This task creates the YAML schema, TypeScript types, loader, and validator for pipeline definitions.

## Context

Part of the Pipeline series (AF-23 through AF-28). AF-24 runs in parallel with AF-23 (no shared dependencies). Together they form the foundation for AF-25 (artifact injection) and AF-26 (pipeline runner).

Current state: There is no pipeline definition format. Phase ordering is implied by documentation, not codified anywhere. This addresses the "NO PIPELINE DEFINITION" caveat from `docs/af-flow.md`.

Related: `docs/pipeline-plan.md` — overall plan, architecture, target YAML format.

## Solution

1. **Define TypeScript interfaces** in `src/lib/pipeline.ts` for the pipeline definition schema: `PipelineDefinition`, `PhaseDefinition`, `GateDefinition`, `InjectDefinition`.

2. **Implement a YAML loader** that reads `.af/pipelines/<name>.yaml`, parses with the `yaml` package (already a dependency), and validates the result against the schema.

3. **Implement a validator** that checks:
   - Required fields present (name, phases)
   - Phase names are unique
   - `requires` references existing phase names (no dangling references)
   - `inject.from` references existing phase names
   - Gate operators are from an allowed set
   - No circular dependencies in `requires`

4. **Create the default `sdlc.yaml`** pipeline definition in `.af/pipelines/`.

5. **Implement a list function** that discovers all `.yaml` files in `.af/pipelines/`.

## Acceptance

- [ ] TypeScript interfaces exist in `src/lib/pipeline.ts` for the full pipeline schema
- [ ] `loadPipeline(afPath, name)` reads and parses `.af/pipelines/<name>.yaml`
- [ ] Validator rejects: missing required fields, duplicate phase names, dangling requires/inject references, circular dependencies, invalid gate operators
- [ ] `listPipelines(afPath)` returns available pipeline names
- [ ] `resolvePhaseOrder(pipeline)` returns phases in topological order
- [ ] Default `sdlc.yaml` pipeline exists with design → implement → verify phases
- [ ] No new npm dependencies (uses existing `yaml` package)
- [ ] Validation errors are descriptive (which field, which phase, what's wrong)

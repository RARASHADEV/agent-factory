# Harden SDK spawn: strip inherited CLAUDE_CODE_* env so af orchestrate/spawn works from within a Claude session

## Objective
Make the Claude Agent SDK wrapper robust when AF is invoked **from inside an
existing Claude Code session**. Right now, the inherited `CLAUDE_CODE_*` /
`CLAUDECODE` environment variables leak into the nested `query()` subprocess and
break it — every Claude-backed run fails with `Claude Code process exited with
code 1`. AF should sanitize the child environment so it works regardless of where
it is launched.

## Context
Surfaced during AF-48 live verification. The first `af orchestrate marketing …`
run failed immediately with `Claude Code process exited with code 1`. Isolated to
`src/lib/sdk.ts` → `runAgent` → `@anthropic-ai/claude-agent-sdk` `query()`, which
spawns a nested `claude` subprocess. The current shell had these set (by the
parent Claude Code session):

```
CLAUDECODE, CLAUDE_CODE_ENTRYPOINT, CLAUDE_CODE_SESSION_ID, CLAUDE_CODE_AGENT,
CLAUDE_CODE_EXECPATH, CLAUDE_CODE_TMPDIR, AI_AGENT, CLAUDE_EFFORT
```

Re-running with those unset made the SDK succeed immediately:
```
env -u CLAUDECODE -u CLAUDE_CODE_ENTRYPOINT -u CLAUDE_CODE_SESSION_ID \
    -u CLAUDE_CODE_AGENT -u CLAUDE_CODE_EXECPATH -u CLAUDE_CODE_TMPDIR \
    -u AI_AGENT -u CLAUDE_EFFORT  node dist/cli.js orchestrate marketing "…"
# → success=true, usage reported, 4 agents ran
```

So this is **environmental, not a logic bug** in AF-48. It affects any AF path that
spawns the SDK (`af orchestrate` and the `af agent spawn` subprocess runner) when
run inside a Claude session (common in dev / CI-on-Claude / agent-driven usage).

## Approach
- In `src/lib/sdk.ts` (and/or wherever the child process/`query()` is configured),
  build a **sanitized environment** for the nested SDK call that removes the
  inherited Claude-session vars before spawning. Prefer an explicit deny-list of the
  known-problematic keys (`CLAUDECODE`, `CLAUDE_CODE_*`, `AI_AGENT`, `CLAUDE_EFFORT`)
  rather than wiping the whole env (auth/`PATH`/locale must survive).
- Confirm `@anthropic-ai/claude-agent-sdk` exposes an `env`/process-options hook; if
  `query()` doesn't accept a custom env, sanitize `process.env` for the duration of
  the call (save/restore) or set the child env via the SDK's documented option.
- Keep credentials working: the file-based `~/.claude` auth must still be honored;
  only strip the session/runtime markers, never auth.
- Apply the same sanitization to the `spawn-runner.js` detached-subprocess path so
  `af agent spawn` is fixed too (verify whether it already inherits the bad vars).

## Acceptance
- [ ] `af orchestrate <domain> "<objective>"` succeeds when launched from **within**
      a Claude Code session (the `CLAUDE_CODE_*` vars present), with no manual `env -u`
- [ ] The nested SDK subprocess receives a sanitized env: Claude-session markers
      removed, but `PATH`, locale, and `~/.claude` auth intact
- [ ] `af agent spawn` (subprocess-runner path) verified to also work from within a
      Claude session (fix applied there too if needed)
- [ ] Sanitization is centralized (single helper / deny-list constant) so future
      spawn sites reuse it; deny-list documented
- [ ] Regression: behavior unchanged when NOT inside a Claude session (vars absent)
- [ ] Test covers the sanitizer (given a polluted env, the spawn env excludes the
      deny-listed keys and retains the rest)

## Notes
- Low complexity but medium impact: without it, AF's Claude backend is unusable in
  the increasingly-common "AF driven by / running inside Claude" scenario.
- Document the workaround (`env -u …`) in the ticket until the fix lands.
- Pairs with AF-48 (`af orchestrate`) and AF-42 (execution backends).

## Design
**Technical design:** `docs/designs/AF-51.md` — full spec (shared sanitizer module,
the SDK `query({ env })` choke-point fix, the agent.ts spawn cleanup, test plan).

Summary of the approach:
- **`src/lib/env-sanitize.ts`** (new) — `CLAUDE_SESSION_ENV_DENYLIST` (the 8 verified
  keys) + `sanitizedSpawnEnv(base=process.env)` returning a full env copy minus those
  keys (keeps PATH/HOME/auth/locale). Pure, single source of truth.
- **`src/lib/sdk.ts`** (edit) — pass `env: sanitizedSpawnEnv()` to `query()`. This is
  the authoritative fix: both `af orchestrate` and `af agent spawn` reach Claude
  through `runAgent`→`query()`, so one line covers both paths.
- **`src/commands/agent.ts`** (edit) — replace the partial `{ ...process.env,
  CLAUDECODE: undefined }` (only 1 of 8 vars) with `sanitizedSpawnEnv()`.
- **Key SDK fact:** `query().options.env` *replaces* the default `process.env`, so we
  must pass a full copy minus the deny-list — not just a few keys (sdk.d.ts:757).
- **No context loss / no new flag / no engine change.** Auth is file-based (~/.claude),
  unaffected.

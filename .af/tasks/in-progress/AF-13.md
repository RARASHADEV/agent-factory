# Auto-create project in Loka + inline sync on task mutations

## Objective

Two things:

1. **Auto-create project:** When `af sync` runs and the project doesn't exist in Loka yet, auto-create it using metadata from `project.md` instead of throwing a `ProviderError`.
2. **Inline sync on mutation:** Every `af task` command (`create`, `move`, `update`) should sync to Loka inline — no separate `af sync` step needed for day-to-day work. `af sync` remains as a reconciliation tool for drift/initial import.

## Context

Currently `af init` does a best-effort project creation in Loka (lines 116-135 in init.ts), but it's silent on failure. If Loka is down during init or the project was never created, `af sync` throws a hard `ProviderError` in `ensureConfig()` and dies. There's no fallback.

Beyond that, task mutations (create, move, update) only write local markdown files. Pushing changes to Loka requires a manual `af sync`. This should be automatic — every task command should sync inline as a side effect.

## What needs to happen

### Part 1: Auto-create project
1. Add `createProject()` method to `LokaHttpClient`
2. In `LokaProvider.ensureConfig()`, instead of throwing when project not found, call `createProject()` using data from `project.md`
3. Log the auto-creation clearly so it's not invisible
4. Proceed with normal sync after creation

### Part 2: Inline sync on mutation
5. After `af task create` writes the markdown file, push the new task to Loka
6. After `af task move` moves the file, update the task status in Loka
7. After any task field update, sync the change to Loka
8. Sync failures on mutation should warn (stderr) but NOT block the local operation — local file is source of truth
9. `af sync` still exists for full reconciliation (bulk import, drift correction)

## Acceptance
- [ ] `af sync` auto-creates the project in Loka when it doesn't exist
- [ ] Project created with correct name, prefix, and description from project.md
- [ ] Auto-creation is logged visibly (not silent)
- [ ] If Loka is unreachable, sync fails gracefully with a clear error (not a cryptic throw)
- [ ] Existing projects are not affected (idempotent)
- [ ] `af init` best-effort creation still works as before (no regression)
- [ ] `af task create` pushes the new task to Loka inline
- [ ] `af task move` updates status in Loka inline
- [ ] Inline sync failures warn but don't block the local operation
- [ ] `af sync` still works as full reconciliation tool

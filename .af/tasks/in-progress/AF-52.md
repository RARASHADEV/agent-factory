# UX Design: Agent Factory web UI — audit, design system, and component specifications

## Objective
Audit the current Agent Factory web UI, identify structural UX problems, and produce actionable design specifications: design tokens, component specs with all states, information architecture, interaction patterns, and a responsive strategy. The output is a reference document for the frontend engineer who will implement the improvements.

## Context
The web UI (`web/`) is a Next.js 16 + Shadcn/ui + Tailwind v4 application. It has five live sections (Chat, Projects, Agents, Domains, Files), with Files being a stub. The application is used primarily by one power user (the owner/Brahma) and agents. Core problems identified:

1. Agents page uses a card grid — too dense visually, too slow to scan at 20+ agents
2. No Tasks view — the core AF value (task management) is invisible from the UI
3. Domains page is read-only with no orchestration trigger
4. Chat empty state forces a two-step flow (see agents → click "More agents" dialog) instead of a direct search
5. Color system is functional but brand-less — opportunity for subtle warmth without AI-color clichés
6. Files page is a stub with no design spec

## Acceptance
- [x] UX audit of all 5 sections with specific, numbered issues
- [x] Design token spec: color palette (with semantic mapping), typography scale, spacing scale, radius/shadow values
- [x] Agents page redesign: list layout spec replacing card grid, all states (loading, empty, selected, hover, 0 agents, 50 agents)
- [x] Tasks view spec (new): filterable task table with status pipeline header, all states
- [x] Chat page improvements: empty state redesign, agent selector pattern
- [x] Domains page: orchestration trigger spec (slide-over panel)
- [x] Responsive breakpoint strategy for all sections
- [x] Accessibility checklist (WCAG AA)
- [x] Interaction patterns (keyboard navigation, focus management)

# AF Service — Agent Factory over HTTP (`af serve`)

## Objective
Expose the Agent Factory command surface as an authenticated HTTP service (`af serve`,
systemd on Hanuman) so any authenticated client dispatches and queries through one governed
door instead of ad-hoc `bash → af` / `ssh … af`. Central, not federated — one process,
one global concurrency queue, one SQLite system-of-record that logs everything the service
does and exposes it as a live overview.

## Context
Full technical design: `docs/designs/AF-53-service.md`. **Self-contained — no external/ORA
dependency** (the prior ORA-160 coupling was removed 2026-06-04 per owner direction; AF is
built as a standalone service for any consumer). The surface splits into two planes:

- **Execution plane** (`agent spawn`, `orchestrate`, `pipeline run/pause/resume`) — flows
  through a global concurrency queue (`AF_MAX_CONCURRENCY=20`), a **SQLite database**
  (Decision 7 — `node:sqlite`; jobs + cross-plane audit journal + lifecycle events), and
  completion callbacks. Every request is logged on arrival and on completion (§5.4). Async:
  dispatch returns a ticket, the result is pushed back.
- **Query / mutation plane** (`projects`, `status`, `task *`, `agent`, `pipeline list/status`,
  `sync`, `init`) — fast synchronous request/response, never queued.

Built in two stages (design §2, §11):
- **Stage A — Execution plane + audit** (the governed core): `af serve` skeleton + auth +
  `POST /jobs` + global queue + SQLite database (registry + audit journal) + log-first/log-last
  middleware + `GET /audit` overview + reconcile-on-boot + completion callbacks +
  `/jobs` · `/audit` · `/health` read service. Role: **ENGINEER**.
- **Stage B — Full surface**: presentation-free core-function refactor (§3.1) + query/mutation
  routes. Role: **ENGINEER** (may involve FRONTEND_ENGINEER later if `web/` is pointed at the API).

## Acceptance (from design §13)
- [ ] Auth: unauthenticated / wrong-secret request → 401
- [ ] Project guardrail: `POST /jobs` with missing/unknown `project` → 400, nothing enqueued
- [ ] Concurrency: 25 jobs from two clients → ≤20 run concurrently, rest queue, none dropped
- [ ] Callback on all terminal states (completed/failed/crashed/timeout) — exactly once, no hang
- [ ] Restart survival: queued jobs resume, orphaned `running` rows → failed and re-dispatchable
- [ ] Query plane is unqueued: `GET /projects` returns immediately while 20 jobs run
- [ ] Parity: a representative query/mutation route returns the same data as the equivalent `af` CLI command
- [ ] Audit log-first/log-last: every job/inquiry/instruction has a `request_log` row written before work and updated before the response; rejected requests still logged; no secret persisted
- [ ] Audit overview: `GET /audit` returns the cross-plane journal (filterable, unqueued) while jobs run
- [ ] Storage: DB opens via `node:sqlite` (Node ≥ 22), no new `package.json` dependency; retention default keeps everything

- **Node ≥ 22** on the host (Hanuman) — required by `node:sqlite` (Decision 7); confirm before deploy (AF-61)
- AF engine — `dispatchAgent`, orchestrator, `spawn-runner.js` (exist; `ENABLE_AF_48` on)
- Core-function refactor (design §3.1) — prerequisite for Stage B breadth
- Loka sync (AF-12) — unchanged (task-board sync; unrelated to the removed ORA coupling)
- Tailscale mesh (exists)

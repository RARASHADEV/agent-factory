# Pipeline Flow 1: Structured agent output — result.json schema and extraction in spawn-runner

## Objective

Agents currently write freeform `result.md` files. A pipeline orchestrator needs machine-readable output to make decisions (did the architect finish? did the engineer produce a PR? did QA pass?). This task adds a `result.json` alongside `result.md` so downstream pipeline phases can programmatically evaluate agent output.

## Context

Part of the Pipeline series (AF-23 → AF-28) that enables autonomous multi-agent SDLC execution. This is the **foundation** — without structured output, pipelines cannot gate or inject artifacts.

Current state: `spawn-runner.ts` writes `result.md` (freeform text) and `status.json` (pid, status, timestamps). Neither contains structured data about *what the agent produced*.

Related: `docs/af-flow.md` — see "NO RESULT VALIDATION" and "UNEVEN OUTPUT SPECS" caveats.

## Solution

1. **Define a `ResultSchema` interface** in a new file `src/lib/result-schema.ts`:
   - `status`: `"complete"` | `"partial"` | `"failed"` | `"blocked"`
   - `artifacts`: array of `{ type: string, path: string }` — files the agent produced
   - `next_role`: optional string — which role should pick up next
   - `blockers`: optional array of strings — what prevented completion
   - `summary`: string — one-line human-readable summary
   - `metadata`: optional record — agent-specific structured data (e.g., `pr_url` for engineer, `verdict` for QA)

2. **Extract `result.json` in `spawn-runner.ts`**: after the agent finishes, scan `result.md` for a fenced JSON block (```json ... ```) matching the schema. If found, write it as `result.json` in the output dir. If not found, synthesize a minimal `result.json` from `status.json`.

3. **Update agent prompts** (architect, engineer, QA) to instruct them to include a `result.json` block in their output. Start with these 3 agents only — expand later.

## Acceptance
- [ ] `ResultSchema` interface exists in `src/lib/result-schema.ts`
- [ ] `spawn-runner.ts` extracts or synthesizes `result.json` after agent completion
- [ ] Architect agent prompt instructs it to emit a result JSON block with `artifacts` listing the design doc path
- [ ] Engineer agent prompt instructs it to emit a result JSON block with `pr_url` in metadata
- [ ] QA agent prompt instructs it to emit a result JSON block with `verdict` in metadata
- [ ] Existing `result.md` and `status.json` behavior is unchanged (backward compatible)
- [ ] Unit/integration test or manual verification that `result.json` is written after a spawn completes

# AF-18: Webhook listener for Loka → AF sync

## Problem

Sync is currently one-way: AF → Loka (push). When a status changes in Loka's UI, local `.af/tasks/` files don't update until someone manually runs `af sync --pull`.

## Solution

Build a lightweight webhook listener in AF that Loka calls on task mutations (status change, assignment, etc.). The listener updates the local task file accordingly — moving it between status folders, updating frontmatter fields.

## Requirements

1. **Webhook endpoint** — AF exposes a small HTTP server (e.g., `af webhook serve` or a daemon) that listens for POST requests from Loka
2. **Loka webhook config** — Loka fires a webhook on task status change, sending task ID, new status, project prefix, and any changed fields
3. **Local file update** — On receiving a webhook, AF resolves the task file by ticket number, moves it to the correct status folder, and updates frontmatter
4. **Idempotency** — Duplicate webhook deliveries must not corrupt state
5. **Auth** — Shared secret or token to prevent unauthorized calls
6. **Logging** — All incoming webhooks logged for auditability

## Architecture Notes

- Loka side: needs a webhook dispatch system (event → POST to configured URL). This may need a corresponding Loka task.
- AF side: minimal HTTP server, could be Express or raw `http.createServer`. Runs as a background daemon or systemd service.
- The pull sync logic from the sync engine can be reused — webhook just triggers a single-task pull instead of a full project pull.

## Acceptance Criteria

- [x] `af webhook serve` starts a listener on a configurable port
- [ ] Loka status change triggers a POST to the AF webhook
- [x] Local task file moves to the correct status folder within seconds
- [x] Duplicate webhooks are handled gracefully
- [x] Webhook calls are authenticated

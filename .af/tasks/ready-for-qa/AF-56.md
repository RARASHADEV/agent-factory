# Global concurrency queue + POST /jobs + GET /jobs/:id

> **Epic:** AF-53 — AF Service over HTTP (`af serve`) · **Stage A (execution plane)** · **Seq 3 of 4**
> **Design:** `docs/designs/AF-53-service.md` §4 (exec plane), §5.1, §5.3, §6, Decisions 1/3/6 · **Flag:** `ENABLE_AF_53`
> **Depends on:** AF-54 (server), AF-55 (registry) · **Blocks:** AF-57 (callbacks fire from queue terminal events)

## User Story
As **a remote client (any authenticated AF consumer)**, I want to `POST /jobs` and immediately get back a ticket + queue position, with a fleet-wide cap of 20 concurrent workers, **so that** dispatch is governed from one place and can never overrun the box no matter how many clients fire at once.

## Context
The heart of the execution plane and the reason the service is central-not-federated — a fleet-wide cap can only be enforced where all execution lives (Hanuman). Every execution request enqueues here; admission, tracking (AF-55), and notification (AF-57) are the only things the service owns — work still runs through existing `dispatchAgent` / `spawn-runner` in the project-local workspace (§5.3). `project` is required and validated against `af projects` **before** enqueue (§6). The queue emits lifecycle transitions (`queued`/`started`/terminal) that **AF-69** persists to `job_events`.

## Acceptance
- [ ] `POST /jobs` with missing/unknown `project` → `400`, nothing enqueued (design test 2, §6).
- [ ] 25 jobs from two clients → ≤20 run concurrently, the rest queue, none dropped (design test 3, Decision 1).
- [ ] `POST /jobs` → `202 { id, status: "queued", queuePosition }`.
- [ ] Queue depth > `AF_MAX_QUEUE_DEPTH` (default 500) → `429 { error, retryAfter }`, nothing enqueued; in-flight jobs unaffected (design test 10, Decision 6).
- [ ] `GET /jobs/:id` and `GET /jobs?project=&status=` return registry state.
- [ ] Supported kinds: `agent` | `orchestration` | `pipeline` (+ `pause`/`resume` for pipelines).

## Sequencing
- **Depends on:** AF-54, AF-55.
- **Blocks:** AF-57 (callbacks fire from queue terminal events).
- **Parallel with:** AF-58, AF-69 (coordinate the `job_events` hooks AF-69 persists).

# systemd unit + deploy af serve on Hanuman

> **Epic:** AF-53 — AF Service over HTTP (`af serve`) · **Cross-cutting — runs last** · **Seq 7**
> **Design:** `docs/designs/AF-53-service.md` §1, §8 (config), §14 (flag removal note) · **Flag:** `ENABLE_AF_53` (flip here)

## User Story
As the **platform operator**, I want `af serve` running as a systemd service on Hanuman bound to the tailnet, **so that** the service survives reboots and I can turn `ENABLE_AF_53` on for the fleet after acceptance passes.

## Context
Final wiring ticket. A minimal Stage-A-only deploy (execution plane + audit) can ship first, with the Stage B routes following — but the flag flip to `true` is gated on the full acceptance run. Mirror the existing local-CLI deploy flow (build → verify) from CLAUDE.md; add the systemd unit + env/config wiring (`AF_SERVICE_*` keys, §8).

**Node precondition (storage):** the service uses Node's built-in `node:sqlite`, which requires **Node ≥ 22** (Decision 7). Confirm Hanuman's Node version before deploy; if it is < 22, upgrade Node on Hanuman first. (Verified locally: dev box is `v22.x`; Hanuman not yet confirmed.)

- [ ] **Hanuman runs Node ≥ 22** (`node --version`); `af serve` opens its SQLite DB via `node:sqlite` with no extra dependency.
- [ ] systemd unit installed on Hanuman (auto-restart, env/config wired from §8 keys, `AF_SERVICE_SECRET` provided, `AF_SERVICE_DB` on persistent storage).
- [ ] Service binds the tailnet interface only (inherits AF-54 fail-closed behaviour); reachable from authenticated clients over Tailscale.
- [ ] Survives a host reboot (queued jobs resume via AF-55 reconcile; audit history intact).

# Mutation routes (write plane)

> **Epic:** AF-53 — AF Service over HTTP (`af serve`) · **Stage B (full surface)** · **Seq 6 (parallel with AF-59)**
> **Design:** `docs/designs/AF-53-service.md` §4 (mutation plane), Decision 5 (capability/audit), §9 · **Flag:** `ENABLE_AF_53`
> **Depends on:** AF-58 (core ops), AF-54 (server) · **Blocks:** AF-61 (deploy)

## User Story
As a **remote client (any authenticated AF consumer)**, I want write endpoints for task create/move/assign/log, sync, init and agent sync behind the same auth — with every mutation audit-logged — **so that** I can drive AF state changes through the governed API instead of `ssh … af`.

## Context
Synchronous writes, thin adapters over AF-58 ops. v1 grants the **full surface to every authenticated client** (single shared secret, Decision 5); per-client least-privilege (capability tokens) is a deferred follow-up, not this ticket. `init` and `sync` are powerful — same auth, but **every mutation flows through the AF-69 log-first/log-last middleware** and is recorded in `request_log` so it is attributable. No generic `exec` passthrough (§9).

## Acceptance
- [ ] Routes per §4: `POST /projects` (init), `POST /projects/:p/tasks` (create), `PATCH /tasks/:ticket` (move/assign/log), `POST /agents/sync`, `POST /sync`.
- [ ] Every mutation + `init`/`sync` call is recorded in `request_log` via the AF-69 middleware (Decision 5, §5.4, §9).
- [ ] A representative mutation returns the same result as the equivalent `af` CLI command (parity, design test 7).
- [ ] Auth enforced (401); unknown `project` → 400; no arbitrary command passthrough.

## Sequencing
- **Depends on:** AF-58 (must land first), AF-54.
- **Parallel with:** AF-59 (query routes) — independent once AF-58 is in.
- **Blocks:** AF-61.

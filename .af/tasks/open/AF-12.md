# Bidirectional Loka sync with assignee propagation

## Objective

Build bidirectional sync between AF's local task files and Loka's API, including assignee propagation so task assignments in either system are reflected in both.

## Context

Tasks exist in two places: `.af/tasks/` (local, file-based, used by agents) and Loka (API, used by Brahma and Ora for visibility). Changes in one should reflect in the other. Assignee is critical — when Ora assigns a task to Garuda in Loka, the local file should update; when an agent picks up a task locally, Loka should show the assignment.

## Acceptance
- [ ] `af sync` command pushes local task state to Loka
- [ ] `af sync --pull` pulls Loka state to local files
- [ ] `af sync --bidirectional` reconciles both directions (conflict resolution: last-write-wins with timestamp)
- [ ] Assignee field propagates in both directions
- [ ] Status changes propagate in both directions
- [ ] New tasks created in either system appear in the other after sync
- [ ] `loka-ref` field in task frontmatter links local task to Loka ticket
- [ ] Tested: create task in Loka, sync, verify local file exists and vice versa

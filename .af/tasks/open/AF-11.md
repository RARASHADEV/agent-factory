# TaskProvider abstraction layer

## Objective

Build a TaskProvider abstraction so AF agents interact with tasks through a uniform interface, regardless of whether tasks are stored as local markdown files or in Loka's API.

## Context

AF uses file-based markdown tasks (`.af/tasks/`). Loka uses an API with database-backed tasks. Agents shouldn't need to know which system they're talking to. The TaskProvider abstracts this — agents call `getTask()`, `updateStatus()`, `addComment()` and the provider routes to the right backend. Design doc at `docs/designs/LOK-26-design.md`.

## Acceptance
- [ ] TaskProvider interface defined (getTask, listTasks, updateStatus, addComment, moveTask)
- [ ] FileTaskProvider implements interface for `.af/tasks/` markdown files
- [ ] LokaTaskProvider implements interface for Loka API
- [ ] AF CLI uses TaskProvider instead of direct file operations
- [ ] Provider selection via config (`.af/project.md` or env var)
- [ ] Tested: same agent workflow works against both providers

# Bug: af sync push reports success but descriptions are not updated in Loka

## User Story

As a user who writes task descriptions locally in markdown files, I want `af sync --mode push` to reliably update those descriptions in Loka, so that my team sees the full task context in the Loka UI without manual intervention.

## Objective

Diagnose and fix why `af sync --mode push` reports tasks as "pushed" but their descriptions remain empty (or stale) in Loka. The sync engine detects the field difference, calls `pushToLoka()`, but the description doesn't arrive in Loka's database.

## Context

**Discovered during:** Pipeline task creation (AF-23 through AF-28). After creating tasks with `af task create` (which sends empty descriptions to Loka) and then filling in the descriptions by editing local files, ran `af sync --mode push --verbose`. Output showed:
```
[sync] Push AF-28 → Loka
[sync] Push AF-27 → Loka
...
✓ Pushed: 10 task(s)
```

No errors. But checking the Loka API directly revealed all 6 tasks still had empty descriptions. A direct `curl -X PATCH` to the same endpoint with the same payload worked (HTTP 200), proving the API accepts description updates.

**Suspected root causes (investigate all):**

1. **Silent PATCH failure:** The `lokaProvider.update()` method sends a PATCH to `/tasks/{id}` with the description field. The response might be 200 but Loka may silently ignore the `description` field in the PATCH body. Check the Loka API contract — does PATCH `/tasks/{id}` actually support updating `description`?

2. **Description comparison mismatch:** The sync engine's `hasContentDifference()` compares `local.description.trim()` vs `remote.description.trim()`. But `pushToLoka()` compares `local.description !== remote.description` (without trim). If one has trailing whitespace, `hasContentDifference` says "different" but `pushToLoka` might not include description in the update payload.

3. **Task matching by ticket number vs loka-ref:** The sync engine matches local tasks to remote tasks first by `loka-ref` (UUID), then by ticket number. If matching works but the resolved `remote.externalId` is wrong, the PATCH goes to the wrong task. (Verified this is NOT the issue — IDs match correctly.)

4. **LokaProvider.update() drops description:** Look at `lokaProvider.update()` — it builds a `body` object and only includes fields that are `!== undefined`. The sync engine's `pushToLoka()` sets `update.description = local.description`, and `lokaProvider.update()` checks `if (input.description !== undefined) body.description = input.description`. This chain looks correct, but should be verified with actual debugging/logging.

5. **Response not checked:** The `lokaProvider.update()` calls `this.client.patch()` and returns the result. But `pushToLoka()` in the sync engine doesn't check the response to verify the description was actually updated. A non-throwing response doesn't mean the field was accepted.

**Key files:**
- `src/lib/sync-engine.ts` — `pushToLoka()` (line 341) and `hasContentDifference()` (line 448)
- `src/lib/providers/loka-provider.ts` — `update()` (line 304)
- `src/lib/providers/loka-http-client.ts` — `patch()` (line 41)

## Solution

1. Add debug logging to `pushToLoka()` that shows exactly which fields are being sent in the PATCH and what response came back
2. Identify why the description field is not persisted
3. Fix the root cause
4. Add a verification step: after pushing, optionally read back the task to confirm the description matches (at least in verbose mode)

## Acceptance
- [ ] `af sync --mode push` reliably updates task descriptions in Loka when the local description differs
- [ ] After running `af sync --mode push`, descriptions in the Loka API match local file content
- [ ] The `--verbose` flag shows which fields are being pushed per task
- [ ] If a push silently fails (API accepts but doesn't persist), a warning is emitted
- [ ] No regression in other synced fields (title, status, priority, assignee)

1. `af task create "test sync desc" -p AF` — creates task with empty description in Loka
2. Edit the local file to add a description body
3. `af sync --mode push --verbose -p AF`
4. Check Loka API: `curl -H "X-Api-Key: ..." "http://localhost:3333/api/v1/tasks?projectPrefix=AF&ticketNumber=XX"`
5. **Expected:** description matches local file
6. **Actual:** description is empty

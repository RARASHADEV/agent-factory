# Pipeline Flow 3: Artifact injection in prompt composition

## Objective

Modify the prompt composition logic so that when an agent is spawned as part of a pipeline, the outputs of prior phases (design docs, PR URLs, QA verdicts) are injected into the system prompt automatically. This is the glue that threads context between agents.

## Context

Part of the Pipeline series (AF-23 → AF-28). Depends on AF-23 (result.json exists) and AF-24 (pipeline definition with `inject` blocks exists).

Today, `agentSpawnCommand()` in `src/commands/agent.ts` composes the system prompt from: agent instructions + project.md + task file + context files. There is **no injection of prior agent output**. The engineer must discover the architect's design doc by convention, not by injection. See `docs/af-flow.md` — "NO ARTIFACT PASSING" caveat.

## Solution

1. **Add an `injectArtifacts()` function** in `src/lib/pipeline.ts` (or a new `src/lib/artifact-injector.ts`):
   - Input: list of `ArtifactInjection` specs (from pipeline phase definition), the ticket ID, the `.af/output/` directory
   - For each injection:
     - Resolve `from` → find the output dir of that phase (`.af/output/{ticket}/{agent}/`)
     - Read `result.json` from that phase
     - If `artifact` is a glob pattern with `{ticket}` → resolve and glob-match files, read content
     - If `artifact` is a `metadata.*` path → extract value from `result.json`
   - Output: array of `{ label: string, content: string }` — ready to splice into a prompt

2. **Modify prompt composition** — add a new `## Prior Phase Output` section to the system prompt when artifact injections are present. Each injected artifact gets a subsection:
   ```
   ## Prior Phase Output

   ### design_document
   <contents of docs/designs/AF-25-feature.md>

   ### pr_to_review
   https://github.com/org/repo/pull/42
   ```

3. **This function is called by the pipeline runner (AF-26)**, not by `agentSpawnCommand` directly. But the prompt composition helper should be reusable — extract it from `agentSpawnCommand` into a shared function so both standalone spawns and pipeline spawns can use it.

## Acceptance
- [ ] `injectArtifacts()` function resolves artifact references from prior pipeline phases
- [ ] Glob patterns with `{ticket}` placeholder are expanded correctly
- [ ] `metadata.*` paths extract values from `result.json`
- [ ] Injected artifacts are formatted as a `## Prior Phase Output` section in the system prompt
- [ ] Prompt composition logic is refactored into a reusable function (used by both standalone spawn and pipeline spawn)
- [ ] If a referenced artifact doesn't exist, a clear error is raised (not a silent empty injection)
- [ ] File content injection has a size cap (e.g., 50KB per artifact) to avoid prompt overflow

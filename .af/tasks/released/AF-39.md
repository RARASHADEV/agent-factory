# Regression tests for pipeline task-refresh bugs (AF-35, AF-38)

## Objective

Add automated tests that would catch the two task-refresh bugs we hit during
the AF-33 pipeline smoke tests:

1. **AF-35** — `pipelineRunCommand` reads a stale `task.filePath` after
   `provider.move` bumps the task from `open/` to `in-progress/`, and the first
   phase fails with ENOENT.
2. **AF-38** — `sharedPhaseLoop` holds one `task` handle across every phase; if
   an agent moves the file mid-pipeline (e.g. engineer moves `in-progress/` →
   `ready-for-qa/`), the next phase's prompt composer fails with ENOENT on the
   stale path.

Both fixes are live on master (`1d4c081` and `2e8aa00`). This ticket closes the
remaining "regression test covers…" AC on AF-35 and AF-38.

## Context

- Fix for AF-35: `src/commands/pipeline.ts` — task handle re-fetched after the
  initial `provider.move`.
- Fix for AF-38: `src/commands/pipeline.ts` — `sharedPhaseLoop` re-fetches the
  task via `provider.get` at the top of every phase iteration, after the pause
  check.
- Existing pipeline tests: `src/__tests__/pipeline-pause-resume.test.ts`
  already uses a `mkProvider()` stub that can be extended or copied.

A verification gap to be aware of: because the fixes are already merged, a
passing test does not by itself prove the test would have caught the bug. The
architect should decide how to close this gap — options include a spy-based
test that asserts the refresh mechanism ran, or a documented revert-verify-
restore check on the PR. Pick one; don't skip it.

## Acceptance

- [x] A regression test exists for the AF-35 scenario (task starts outside
      `in-progress/`, pipeline must survive the move)
- [x] A regression test exists for the AF-38 scenario (phase agent moves the
      task file mid-pipeline, next phase must not fail)
- [x] Both tests pass on master
- [x] Verification that the tests would catch the bugs is documented in the PR
      (architect's choice of mechanism — spy assertion, revert-verify-restore,
      or equivalent)
- [x] `npx tsx --test src/__tests__/pipeline-*.test.ts` passes end-to-end

## Non-goals

- No production-code changes — the fixes are already live
- No broader pipeline test refactor — keep scope to these two scenarios
- No new test framework or fixture library — use what's already in the repo

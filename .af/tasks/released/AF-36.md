# Engineer agent git stash -u swallows pipeline output dirs — artifacts never restored

## Summary

During the implement phase, the engineer agent runs `git stash -u` (or equivalent)
to snapshot working-tree state before cutting its feature branch. Because
`.af/output/` is **not** in `.gitignore`, this stash pulls in the pipeline's own
output directories — `.af/output/<ticket>/architect/`, `.af/output/<ticket>/engineer/`
— including their `agent.log` and `result.json` files.

The stash is never popped, so after the engineer phase those artifacts are gone
from disk. Downstream consequences:

- **Artifact injection breaks.** QA phase declares `inject: design_document ← design phase`
  which expects the architect's output. With the architect's output stashed, injection
  would fail if verify ever ran.
- **Post-mortem is blind.** When a phase fails, the first thing you want is
  `agent.log` and `result.json`. Both are in the stash.
- **Gate evaluation can't work.** The engineer's `result.json` is what the gate
  reads to check `metadata.pr_url`. If it's stashed, the gate has nothing to read
  even when the engineer succeeded.

## Reproduction

1. Run `af pipeline run sdlc --task <TICKET>` on any task (use AF-33's workaround
   path — see AF-35 — to get past the first bug)
2. After the engineer phase, inspect `.af/output/<TICKET>/`
3. Expected: directories `architect/` and `engineer/` with `agent.log` and
   `result.json`
4. Actual: only `pipeline-state.json` is present; other contents are in `git stash`

Repro captured 2026-04-15 during AF-33 smoke test:
- `ls .af/output/AF-33/` → only `pipeline-state.json`
- `git stash list` → `stash@{0}: WIP on master` (contains the missing dirs)

## Root cause

`.gitignore` currently contains:
```
node_modules/
dist/
.env
.af/audit.log
```

It does **not** include `.af/output/`. `git stash --include-untracked` (the flavor
most agents use) grabs every untracked file that isn't gitignored, which happily
scoops the pipeline's runtime output into the stash.

## Fix options

**Option A (minimal, recommended):** Add `.af/output/` to `.gitignore`. One-line
change. `git stash -u` leaves ignored files alone, so pipeline outputs stay on
disk.

**Option B (defensive):** Have the pipeline runner refuse to proceed if its
output directory is missing after a phase completes, and restore from stash or
re-run as needed. More code, more complexity, protects against agents using
`git stash -a` (which stashes ignored files too).

**Option C (agent-prompt change):** Tell the engineer agent not to `git stash -u`
— use targeted `git stash push -- <paths>` instead. Fragile; depends on agent
compliance.

**Recommendation: A + note in agent prompts** that `.af/output/` is runtime
artifacts and should not be committed or stashed.

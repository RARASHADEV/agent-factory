# AF-16: AF → Loka post-action sync hook

## Description

After every AF CLI task mutation (`af task move`, `af task create`, `af task edit`, `af task log`, etc.), automatically trigger a sync to Loka. No manual `af sync` needed.

Additionally, comments/logs must be included in the sync. Today, FileProvider.log() appends to the task markdown and LokaProvider.log() posts to `/tasks/{id}/comments`, but the sync engine ignores both. Comments should flow AF → Loka as part of the auto-sync.

## Requirements

- Add a post-action hook in the AF CLI that fires after any task write operation (including `af task log`)
- The hook calls the sync engine (AF-12/AF-13) for the changed task only — not a full project sync
- Should be non-blocking — CLI returns immediately, sync happens in background
- If sync fails (Loka unreachable), log a warning but don't block the CLI operation
- No cron, no polling — event-driven only
- **Comment/log sync:** When an AF task gets a new log entry, that entry should be synced to Loka as a comment. The sync engine must track which log entries have already been synced to avoid duplicates.

## Acceptance Criteria

- [x] `af task move AF-16 in-progress` automatically syncs AF-16's status to Loka
- [x] `af task create` automatically creates the task in Loka
- [x] `af task log AF-16 "Fixed the bug"` syncs the log entry as a Loka comment
- [x] Log entries are not duplicated on repeated syncs (idempotent)
- [x] Sync failure doesn't block CLI operation
- [x] Works with `ENABLE_AF_12=true` (no-op when sync is disabled)

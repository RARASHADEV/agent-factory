# AF-50: Orchestration Output Persistence — Technical Design

> Make every `af orchestrate` run durably save its output. The engine already
> returns everything; this connects that result to the existing `.af/output/`
> persistence convention. **Glue + a small writer module + presentation — no
> engine changes.**

**Author:** Architect · **Date:** 2026-06-02 · **Implementation role:** ENGINEER (backend/CLI only) · **Complexity:** medium · **Depends on:** AF-48 (shipped)

---

## 1. Overview

`af orchestrate` runs agents **in-process** (the deliberate AF-48 decision so the
supervisor can plan on each agent's output synchronously). It collects everything
into an `OrchestrationResult`, renders a summary table, and then **discards the
actual output text**. Nothing is written to disk — unlike `af agent spawn`, whose
detached `spawn-runner.js` writes `result.md` / `result.json` / `status.json` to
`.af/output/<ticket>/` (AF-23).

The data we want is already in hand: `OrchestrationResult` carries every
`step.output`, `step.backend`, `step.usage`, the `finalizers` map, `approved`,
`totalUsage`, `stopReason`, `dryRun`, and `plan` (`src/lib/orchestrator.ts:59-74`).

This design adds **always-on persistence at the command layer**, reusing the
`.af/output/` convention. After a run, the command writes a run directory and
prints its path. The orchestration **engine stays a pure function** — no file I/O
added there.

### The one design principle
> Persistence is **structural, not optional.** No flag, no `--json` piping
> required. You cannot complete a non-dry-run orchestration without its output
> being saved — and if the disk write fails, the result is dumped to stdout as a
> fallback so it is **never** lost.

---

## 2. Scope

| In scope (AF-50) | Out of scope |
|------------------|--------------|
| Write `result.json` (full `OrchestrationResult`) per run | Changing the engine / control loop |
| Write each delegated step's output to `step-NN-<agent>.md` | Streaming/incremental persistence mid-run |
| Write each finalizer output to `finalizer-<slug>.md` | Resumability / replay from saved runs |
| Write a human `summary.md` mirroring the console report | Loka upload of orchestration artifacts |
| Print the absolute run-dir path on completion | Retention/cleanup policy for old runs |
| Stdout fallback if disk write fails (no data loss) | Persisting the supervisor's own planning turns* |
| Unit test with a stubbed `OrchestrationResult` | — |

\* The supervisor's per-turn raw output is not in `OrchestrationResult` (only its
parsed effect — the resulting `steps`). Capturing supervisor turns is a possible
future enhancement; out of scope here.

---

## 3. Architecture

### Where persistence lives

```
src/commands/orchestrate.ts (orchestrateCommand)
  └─ result = await orchestrator.run(...)        ← AF-46 engine, PURE (unchanged)
  └─ if (!result.dryRun):
        outputDir = persistOrchestrationResult(result, { cwd: process.cwd() })   ← AF-50 NEW
  └─ if (--json) print JSON   else renderReport(result)
  └─ print "saved to <outputDir>"                ← AF-50 NEW
```

- **`src/lib/orchestration-output.ts`** (NEW) — `persistOrchestrationResult(result, opts)`:
  the entire writer. Pure-ish: takes the result + a `cwd` (and an injectable `now`
  for deterministic tests), creates the run dir, writes the files, returns the path.
- **`src/commands/orchestrate.ts`** (EDIT) — call the writer after `run()`, print the
  path, and provide the stdout fallback on write failure.
- **Engine (`orchestrator.ts`): untouched.** Keeping it a pure function preserves its
  testability and matches the AF-48 boundary discipline (I/O at the CLI edge, engine
  stays agnostic).

### Why a separate module (not inline in the command)
Mirrors how `af-dispatch.ts` was split from `orchestrate.ts` in AF-48: the writer is
independently unit-testable (point it at a temp `cwd`, assert files), and the command
stays thin glue + presentation.

## 4. Output Layout

Reuses the `.af/output/` root (`AF_DIR = '.af'`, `src/lib/constants.ts`) that
`af agent spawn` already uses, namespaced under `orchestrate/`:

```
.af/output/orchestrate/<domain>/<run-id>/
    result.json              # full OrchestrationResult (machine-readable)
    summary.md               # human report (same content as the console render)
    step-01-researcher.md    # step.output text, one file per delegated step
    step-02-product-analyst.md
    step-03-content-writer.md
    finalizer-qa.md          # one file per finalizer output
```

- **`<domain>`** — `result.domain` (already a safe slug; validated by AF-43).
- **`<run-id>`** — sortable UTC timestamp, filesystem-safe:
  `new Date(now()).toISOString().replace(/[:.]/g, '-')` → e.g. `2026-06-02T14-30-00-000Z`.
  `Date.now()`/`new Date()` are used freely elsewhere in CLI/runner code
  (`agent.ts`, `spawn-runner.ts`); the injectable `now` keeps tests deterministic.
- **Filenames** — `step-${String(i+1).padStart(2,'0')}-${sanitize(agent)}.md`.
  `sanitize` = lowercase, keep `[a-z0-9-_]`, replace the rest with `-` (defensive;
  roster slugs are already safe).
- **Output serialization** — `step.output` is `unknown`. If it's a string, write
  verbatim; otherwise `JSON.stringify(output, null, 2)`. Same for finalizer outputs.

## 5. New Module: `src/lib/orchestration-output.ts`

```ts
import { mkdirSync, writeFileSync } from 'fs';
import { join } from 'path';
import { AF_DIR } from './constants.js';
import type { OrchestrationResult } from './orchestrator.js';

export interface PersistOptions {
  /** Project root; the run dir is created under <cwd>/.af/output/orchestrate/. */
  cwd: string;
  /** Injectable clock (ms) for a deterministic run-id in tests. Defaults to Date.now. */
  now?: () => number;
}

/**
 * Write an OrchestrationResult to .af/output/orchestrate/<domain>/<run-id>/.
 * Returns the absolute run directory. Throws on I/O failure (caller handles
 * the stdout fallback). Never called for dry runs.
 */
export function persistOrchestrationResult(
  result: OrchestrationResult,
  opts: PersistOptions,
): string {
  const now = opts.now ?? Date.now;
  const runId = new Date(now()).toISOString().replace(/[:.]/g, '-');
  const dir = join(opts.cwd, AF_DIR, 'output', 'orchestrate', result.domain, runId);
  mkdirSync(dir, { recursive: true });

  // 1. Machine-readable full result.
  writeFileSync(join(dir, 'result.json'), JSON.stringify(result, null, 2));

  // 2. Human summary (same content the console renders).
  writeFileSync(join(dir, 'summary.md'), renderSummaryMarkdown(result));

  // 3. One file per delegated step.
  result.steps.forEach((step, i) => {
    const name = `step-${String(i + 1).padStart(2, '0')}-${sanitize(step.agent)}.md`;
    writeFileSync(join(dir, name), stringifyOutput(step.output));
  });

  // 4. One file per finalizer.
  for (const [slug, output] of Object.entries(result.finalizers)) {
    writeFileSync(join(dir, `finalizer-${sanitize(slug)}.md`), stringifyOutput(output));
  }

  return dir;
}

function stringifyOutput(output: unknown): string {
  if (typeof output === 'string') return output;
  if (output == null) return '(no output)';
  return JSON.stringify(output, null, 2);
}

function sanitize(s: string): string {
  return s.toLowerCase().replace(/[^a-z0-9-_]+/g, '-').replace(/^-+|-+$/g, '') || 'agent';
}

function renderSummaryMarkdown(result: OrchestrationResult): string {
  // Markdown twin of renderReport(): objective, per-step table
  // (#, agent, backend, in/out tokens), finalizer verdicts, footer
  // (stopReason, approved, steps, totalUsage). Pure string building.
  // ...
}
```

**Notes for the engineer**
- `renderReport` in `orchestrate.ts` and `renderSummaryMarkdown` here both describe
  the same result — consider factoring the shared shaping (per-step rows, finalizer
  verdict logic from `orchestrate.ts:124-133`) into one helper to avoid drift, but a
  small duplication is acceptable since one targets ANSI console and one targets
  plain markdown.
- Do **not** import this module into `orchestrator.ts`. It is called only from the
  command.

## 6. Command Changes: `src/commands/orchestrate.ts`

Insert persistence after `run()` returns, inside the existing `try` (lines 66-79):

```ts
const result = await orchestrator.run(domain, objective, { ... });

// AF-50: structural persistence — always on for real runs.
let outputDir: string | undefined;
if (!result.dryRun) {
  try {
    outputDir = persistOrchestrationResult(result, { cwd: process.cwd() });
  } catch (writeErr) {
    // Never lose the output: fall back to stdout, flag the failure.
    const msg = writeErr instanceof Error ? writeErr.message : String(writeErr);
    console.error(chalk.red(`Failed to persist orchestration output: ${msg}`));
    console.error(chalk.yellow('Dumping full result to stdout so it is not lost:'));
    console.log(JSON.stringify(result, null, 2));
    process.exitCode = 1;
  }
}

if (options.json) {
  console.log(JSON.stringify(result, null, 2));
} else {
  renderReport(result);
}

if (outputDir) {
  console.log('');
  console.log(dim(`output saved to ${outputDir}`));
}
```

- **Dry run:** persist **nothing** (it dispatched nothing; the plan is already on
  stdout via the live logger and in `result.plan`). Documented behavior.
- **`--json`:** unchanged — still prints to stdout, **and** the run is persisted.
- The persistence block sits inside the same `try` so a thrown error from `run()`
  still hits the existing §6 error handler (unchanged).

## 7. Data Model

No database, no schema migration. `result.json` is a verbatim serialization of the
existing `OrchestrationResult` interface — no new persisted type is introduced. The
per-step/finalizer `.md` files are plain text extracted from that same object.

---

## 8. Error Handling

| Condition | Handling |
|-----------|----------|
| `mkdirSync`/`writeFileSync` fails (permissions, disk full) | Catch in the command, print a red error, **dump full `result.json` to stdout**, set `process.exitCode = 1`. Output is never lost. |
| `result.output` is a non-serializable value (cycles) | `JSON.stringify` throwing is caught by the same block; the per-step `.md` still uses `stringifyOutput` which only stringifies that one value — wrap each `writeFileSync` loop iteration defensively if a single bad step shouldn't sink the whole save. |
| Dry run | Skip persistence entirely (documented). |
| Engine `run()` throws | Unchanged — existing §6 handler (no persistence attempted). |

**Guarantee:** for any non-dry run that reaches the persistence step, the output is
either on disk **or** printed to stdout. There is no silent-loss path.

---

## 9. Security Considerations

- **No secrets written.** `OrchestrationResult` contains only agent outputs,
  `backend` strings, token counts, `stopReason`, and `approved`. It does **not**
  contain endpoints, env, model credentials, or prompts (AF-48 §7 already keeps
  those out of the result). The writer serializes the result as-is; it must not add
  any env/endpoint/credential fields.
- **Path containment.** The run dir is built from `result.domain` (an AF-43-validated
  slug) and a timestamp — no user free-text reaches the path. `sanitize()` defends
  filenames against slug drift. No path traversal surface.
- **Output is agent-authored text.** Written as inert `.md`/`.json`; never executed.

---

## 10. Feature Flag

**No new flag.** Persistence is intrinsic to `af orchestrate`, which is already
gated by `ENABLE_AF_48`. It is additive and safe (writes only under `.af/output/`),
so it ships **always-on** within the command. (If rollout caution is later desired,
it could be gated, but the AF-50 requirement is explicitly *structural/unconditional*
— a flag would contradict that.)

## 11. Test Plan

**Unit — `src/__tests__/orchestration-output.test.ts` (new):**
- `persistOrchestrationResult` against a stubbed `OrchestrationResult` written to a
  **temp `cwd`** (e.g. `mkdtempSync`), with an injected `now` for a fixed run-id:
  - creates `.af/output/orchestrate/<domain>/<run-id>/`
  - writes `result.json` whose parsed content deep-equals the input
  - writes one `step-NN-<agent>.md` per step, padded numbering, with the step's text
  - writes `finalizer-<slug>.md` per finalizer
  - writes `summary.md` containing the stopReason and per-step agents
  - string vs object `output`: string written verbatim; object pretty-JSON
  - `sanitize` handles an odd slug without escaping the directory
  - returns the absolute run-dir path

**Command-level — extend `src/__tests__/orchestrate-command.test.ts`:**
- A non-dry run (deterministic injected planner/executor or stubbed result) persists a
  run dir and prints `output saved to …`.
- `--dry-run` persists **nothing** (no `orchestrate/` dir created).
- Write-failure path (point `cwd` at a non-writable location, or stub the writer to
  throw): prints the failure + dumps JSON to stdout + sets exit code 1.

**Regression:** full suite green (`npx tsx --test src/__tests__/*.test.ts`),
`npx tsc --noEmit` clean, `node dist/cli.js orchestrate --help` unchanged.
